Senior Quantitative Analysis interview guide

Use a structured, supervised work sample: ask the candidate to explain a failure, repair it, and demonstrate how they know the repair works. Combine that with one short case in which requirements and data limitations emerge in stages.

The ten questions form a bank, not a single interview. Four selected questions plus one case are enough for a 75-minute round. This pack assumes practical Python, pandas and NumPy are relevant to the role. Difficulty and timing are proposed calibration levels, not measured hiring thresholds.

LLM access weakens an unsupervised test as evidence of independent coding ability. It does not remove the value of coding in an interview. A supervised repair and an unannounced change of requirement make the candidate's reasoning and implementation visible.

  • Use a company laptop with a prepared local editor or notebook. The interviewer stays present. Keep external assistants and communication tools unavailable for this exercise; a short printed or offline API reference is reasonable if offered consistently.
  • Give the intention, code and actual output together. Ask: what causes this result, what would you change, and what test would catch it? Let the candidate read silently before explaining.
  • Require at least one runnable repair. A whiteboard or spoken outline alone can miss whether someone can translate an idea into Python. If necessary, the interviewer can type under the candidate's explicit direction.
  • Tell candidates that library syntax can be looked up in the provided reference. Score their choice of operations and tests, rather than exact recall of parameter names.
  • Use the same core route and staged hints for a hiring cohort. Record which hints were used. Rotate equivalent variants between cohorts after checking them.
  • Keep finance conventions, model selection theory and ML depth for round two. In round one, score Python correctness, data handling, testing, information timing and engineering judgement.
  • Q9 and Q10 are stretch items. Do not require every senior candidate to finish them, and do not let one memorised trick compensate for weak performance on core tasks.
  • For a 60-minute interview, use 5 minutes introduction, 25 minutes debugging, 20 minutes for one case, 5 minutes follow-up and 5 minutes candidate questions.

Consistent hints and follow-ups

Start with no hint. If the candidate stalls, ask them to trace the smallest failing example. Next offer the question-specific hint below. Finally, identify the relevant area if needed and see whether they can complete the repair. Record the help given; do not silently compare a heavily prompted solution with an independent one.

Once a repair works, change one condition: shuffle input, add an empty group, repeat a key, or introduce a delayed record. Ask the candidate to predict the result before running it. One well-chosen change usually provides more evidence than rushing to another puzzle.

Question 1 Adjacent changes

Difficulty 1 of 5 · Suggested time 3 to 4 minutes

Candidate brief

Return the change between each adjacent pair in a finite list of numbers, in order. An empty or one-element list returns an empty list. Do not change the input.

def changes(values):
    return [values[i] - values[i - 1]
            for i in range(len(values))]

print(changes([100, 105, 102]))

Actual output from the faulty code

[-2, 5, -3]

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

At i = 0, negative indexing reads the last element, creating an unintended last-to-first change. Start at index 1. A zip of values with values[1:] is also correct.

def changes(values):
    return [values[i] - values[i - 1]
            for i in range(1, len(values))]

print(changes([100, 105, 102]))

Corrected output

[5, -3]

Tests to expect

Empty input; a singleton; constant values; negative changes; input unchanged.

Hint

Trace the first iteration and state what index -1 means.

Follow-up

How would you process a stream without storing all observations?

Evidence of senior ability

A senior candidate explains the boundary error, tests empty input, and can describe a one-pass iterator version. Do not demand that version in the warm-up.

Question 2 Missing observations and valid zeroes

Difficulty 1 of 5 · Suggested time 3 to 5 minutes

Candidate brief

Calculate the arithmetic mean, excluding only None. Zero is a valid observation. Return None if there are no valid observations. Inputs contain finite numbers or None; NaN is outside this question's contract.

def mean_valid(values):
    clean = [x for x in values if x]
    return sum(clean) / len(clean) if clean else None

print(mean_valid([0.0, 2.0, None, 4.0]))

Actual output from the faulty code

3.0

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

The truth-value filter removes both None and numerical zero. An explicit identity check preserves zero. The empty-data policy is part of the specification, so returning None is intentional.

def mean_valid(values):
    clean = [x for x in values if x is not None]
    return sum(clean) / len(clean) if clean else None

print(mean_valid([0.0, 2.0, None, 4.0]))

Corrected output

2.0

Tests to expect

All missing; empty; all zero; mixed positive and negative; one valid observation.

Hint

Which different input values evaluate as false?

Follow-up

If NaN becomes an accepted missing value, how would you change the contract and tests?

Evidence of senior ability

Preserves economically meaningful zeroes and distinguishes a missing observation from an observed zero. A one-pass implementation is welcome but not required.

Question 3 Unexpected state between calls

Difficulty 2 of 5 · Suggested time 5 to 7 minutes

Candidate brief

When bucket is omitted, start a new list for that call. If the caller supplies a list, append to that same list and return it.

def record(value, bucket=[]):
    bucket.append(value)
    return bucket

a = record(10)
b = record(20)
print(a, b, a is b)

Actual output from the faulty code

[10, 20] [10, 20] True

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

The default list is created once at function definition. Both calls mutate and return the same object; a changes when the second call runs. Use None as a sentinel and create a new list inside the function. Do not use bucket or []: that would replace an explicitly supplied empty list.

def record(value, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(value)
    return bucket

a = record(10)
b = record(20)
print(a, b, a is b)

Corrected output

[10] [20] False

Tests to expect

Repeated omitted-argument calls; object identity; explicitly supplied empty and nonempty lists.

Hint

When is the default expression evaluated? Are a and b the same object?

Follow-up

What changes if the API must never mutate a supplied list?

Evidence of senior ability

Explains aliasing, preserves the specified ownership contract, and tests identity as well as equality.

Question 4 A stream counted twice

Difficulty 2 of 5 · Suggested time 5 to 7 minutes

Candidate brief

Return (total, count) for a finite iterable of integers. It may be a single-use generator too large to materialise. Use one pass and constant auxiliary memory. Empty input returns (0, 0).

def summarise(values):
    total = sum(values)
    count = sum(1 for _ in values)
    return total, count

print(summarise(x for x in [2, 4, 6]))

Actual output from the faulty code

(12, 0)

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

The first sum exhausts the generator. The second traversal sees no values. Accumulate total and count in one loop. list(values) fixes this fixture but violates the memory requirement; tee may buffer the stream if its branches are consumed separately.

def summarise(values):
    total = count = 0
    for value in values:
        total += value
        count += 1
    return total, count

print(summarise(x for x in [2, 4, 6]))

Corrected output

(12, 3)

Tests to expect

List and generator agree; empty and singleton streams; a source that rejects a second traversal.

Hint

Can this particular object be traversed a second time?

Follow-up

How would you handle malformed rows without silently losing information?

Evidence of senior ability

Distinguishes iterable from iterator, respects the memory constraint, and states O(n) time and O(1) auxiliary space.

Question 5 Labels lost during assignment

Difficulty 3 of 5 · Suggested time 6 to 8 minutes

Candidate brief

Attach each score to the row with the matching id, preserving row order. Score labels are unique and every row id is present in scores; repeated ids in the rows are permitted.

import pandas as pd

def attach_scores(rows, scores):
    return rows.assign(score=scores.to_numpy())

rows = pd.DataFrame({"id": ["B", "A"]})
scores = pd.Series([0.1, 0.9], index=["A", "B"])
print(attach_scores(rows, scores).to_dict("records"))

Actual output from the faulty code

[{'id': 'B', 'score': 0.1}, {'id': 'A', 'score': 0.9}]

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

Converting to an array discards the labels and assigns by position. Match on id using map, or use a validated join. Merely assigning the labelled Series directly also fails here because rows has an integer index rather than an id index.

import pandas as pd

def attach_scores(rows, scores):
    return rows.assign(score=rows["id"].map(scores))

rows = pd.DataFrame({"id": ["B", "A"]})
scores = pd.Series([0.1, 0.9], index=["A", "B"])
print(attach_scores(rows, scores).to_dict("records"))

Corrected output

[{'id': 'B', 'score': 0.9}, {'id': 'A', 'score': 0.1}]

Tests to expect

Shuffle score order; reorder rows; repeated row ids; nondefault row index; empty rows; input unchanged.

Hint

Which labels survive to_numpy, and which labels should determine the match?

Follow-up

What policy would you choose for missing scores or duplicate score labels?

Evidence of senior ability

Separates position, index, and business key. Proposes explicit duplicate and unmatched-key checks when the contract broadens.

Question 6 A join inflates the total

Difficulty 3 of 5 · Suggested time 8 to 10 minutes

Candidate brief

Attach one category to each sale without changing the number of sales or their total quantity. The lookup may contain exact repeated rows, which may be collapsed. Conflicting categories for a sku and unmatched sale skus must raise an error. Sale rows are legitimate separate records. All keys and categories are nonmissing strings.

import pandas as pd

def enrich(sales, lookup):
    return sales.merge(lookup, on="sku")

sales = pd.DataFrame({
    "sale_id": [1, 2], "sku": ["A", "B"], "qty": [10, 20]
})
lookup = pd.DataFrame({
    "sku": ["A", "A", "B"], "category": ["X", "X", "Y"]
})
out = enrich(sales, lookup)
print(len(out), int(out["qty"].sum()))

Actual output from the faulty code

3 40

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

The two A lookup rows each match the same sale, multiplying it. Collapse exact lookup duplicates only; a many-to-one validation then rejects conflicting mappings. A left join preserves sales and the merge indicator detects missing matches. Deduplicating the merged facts or arbitrarily keeping one category can hide a real problem.

import pandas as pd

def enrich(sales, lookup):
    unique = lookup.drop_duplicates()
    out = sales.merge(
        unique, on="sku", how="left",
        validate="many_to_one", indicator=True
    )
    if out["_merge"].ne("both").any():
        raise ValueError("Unmatched sku")
    return out.drop(columns="_merge")

sales = pd.DataFrame({
    "sale_id": [1, 2], "sku": ["A", "B"], "qty": [10, 20]
})
lookup = pd.DataFrame({
    "sku": ["A", "A", "B"], "category": ["X", "X", "Y"]
})
out = enrich(sales, lookup)
print(len(out), int(out["qty"].sum()))

Corrected output

2 30

Tests to expect

Row count and total conserved; legitimate repeated sales retained; conflicting lookup rejected; unmatched sku rejected; empty sales accepted.

Hint

How many output rows can one A sale produce?

Follow-up

What checks would you put before and after a production join?

Evidence of senior ability

Reasons about table grain and join cardinality, does not delete valid facts, and makes invalid states visible.

Question 7 A square array hides a shape error

Difficulty 3 of 5 · Suggested time 7 to 10 minutes

Candidate brief

For a 2D array x with one observation per row and one variable per column, compute the weighted sum of variables for each row. w is a column vector of shape (number of variables, 1). Reject incompatible shapes. Inputs are finite real numbers.

import numpy as np

def weighted_rows(x, w):
    return (x * w).sum(axis=1)

x = np.array([[1., 2.], [3., 4.]])
w = np.array([[0.25], [0.75]])
print(weighted_rows(x, w).tolist())

Actual output from the faulty code

[0.75, 5.25]

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

With these square inputs, broadcasting applies the weights down the rows rather than across the variables. The valid shape masks the wrong calculation. A matrix-vector product expresses the intended reduction. (x * w.T).sum(axis=1) also works under the stated shape contract.

import numpy as np

def weighted_rows(x, w):
    x, w = np.asarray(x), np.asarray(w)
    if x.ndim != 2 or w.shape != (x.shape[1], 1):
        raise ValueError("Incompatible shapes")
    return x @ w[:, 0]

x = np.array([[1., 2.], [3., 4.]])
w = np.array([[0.25], [0.75]])
print(weighted_rows(x, w).tolist())

Corrected output

[1.75, 3.75]

Tests to expect

Non-square inputs; single active variable; output shape; no rows; incompatible weights.

Hint

Write the shapes next to the multiplication. Which axis does each weight vary along?

Follow-up

What could go wrong if you simply flatten every incoming array?

Evidence of senior ability

Explains broadcasting using dimensions and deliberately tests a non-square case. Flattening is acceptable only when justified by the input contract.

Question 8 A rolling feature crosses an entity boundary

Difficulty 4 of 5 · Suggested time 10 to 12 minutes

Candidate brief

For each entity and day, return the mean of that entity's previous two observations, excluding the current observation. Return missing until two previous observations exist. Sort the output by entity and day. Keys are unique; each entity is observed daily without gaps in this fixture.

import pandas as pd

def prior_means(df):
    out = df.sort_values(["entity", "day"]).copy()
    out["prior_mean"] = (
        out.groupby("entity")["qty"]
        .transform(lambda s: s.rolling(2, min_periods=2).mean())
        .shift(1)
    )
    return out

df = pd.DataFrame({
    "entity": ["B", "A", "A", "B", "A", "B"],
    "day": [2, 3, 1, 1, 2, 3],
    "qty": [200, 30, 10, 100, 20, 300]
})
out = prior_means(df)
print(out[["entity", "day", "prior_mean"]]
      .to_csv(index=False, na_rep="NA"), end="")

Actual output from the faulty code

entity,day,prior_mean
A,1,NA
A,2,NA
A,3,15.0
B,1,25.0
B,2,NA
B,3,150.0

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

The rolling calculation is grouped, but the final shift acts on the entire concatenated Series. It moves A's final value into B's first row. Put the shift inside each group. A global shift before grouping can create a similar boundary problem.

        )

    return out

df = pd.DataFrame({

    "day": [2, 3, 1, 1, 2, 3],
    "qty": [200, 30, 10, 100, 20, 300]
})
out = prior_means(df)
print(out[["entity", "day", "prior_mean"]]
      .to_csv(index=False, na_rep="NA"), end="")

A,1,NA
A,2,NA
A,3,15.0
B,1,NA

Tests to expect

First two rows of every entity missing; shuffled input invariant; changing the current observation does not change its feature; groups independent; empty input.

Hint

Is the final shift still inside a group operation?

Follow-up

How does 'two observations' differ from 'two calendar days' if dates are missing?

Evidence of senior ability

Tests the information boundary and group independence, not just the displayed middle rows. Identifies how missing dates would change the specification.

Question 9 Variance disappears through cancellation

Difficulty 4 of 5 · Suggested time 10 to 15 minutes

Candidate brief

Compute population variance (divide by n) for a finite, possibly single-use iterable of finite floats. Use one pass and constant auxiliary memory. Empty input raises ValueError; a singleton has variance zero. The fixture has a large level and small spread.

def population_variance(values):
    n = 0
    total = total_sq = 0.0
    for x in values:
        n += 1
        total += x
        total_sq += x * x
    if n == 0:
        raise ValueError("Empty input")
    return total_sq / n - (total / n) ** 2

values = [1e9 + 1, 1e9 + 2, 1e9 + 3]
print(f"{population_variance(iter(values)):.6f}")

Actual output from the faulty code

0.000000

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

The two terms in E[x squared] minus E[x] squared are large and nearly equal. Floating-point rounding destroys the small difference. The repair uses an online mean and a sum of squared deviations (Welford's recurrence). Clipping a negative result to zero would not recover lost accuracy. This method improves stability; it does not make floating-point arithmetic exact.

def population_variance(values):
    n = 0
    mean = m2 = 0.0
    for x in values:
        n += 1
        delta = x - mean
        mean += delta / n
        m2 += delta * (x - mean)
    if n == 0:
        raise ValueError("Empty input")
    return m2 / n

values = [1e9 + 1, 1e9 + 2, 1e9 + 3]
print(f"{population_variance(iter(values)):.6f}")

Corrected output

0.666667

Tests to expect

Compare with an independent reference; translate small data by a large constant; constant values; singleton; empty; one-use iterator.

Hint

The mathematical identity is correct. What happens when two rounded numbers near 10^18 are subtracted?

Follow-up

Explain the update for m2, or propose a centred two-pass calculation and explain why it misses the streaming requirement.

Evidence of senior ability

Recognises numerical cancellation. Full repair credit requires meeting the one-pass contract; an accurate two-pass proposal earns partial credit. Do not make recall of the algorithm's name a requirement.

Question 10 Historical records that were not yet available

Difficulty 5 of 5 · Suggested time 15 to 20 minutes

Candidate brief

Attach a price to each decision, preserving decision order. Times are integer minutes from a common origin. For the same symbol, eligible quotes have event_min <= decision_min, available_min <= decision_min, and event age at most 5 minutes inclusive. Choose the greatest event_min, then the greatest available_min for revisions of that event. A late older event must not replace a newer event. Return missing if none qualifies. Decision ids are unique. Quote (symbol, event_min, available_min) keys are unique. Inputs contain no missing fields and available_min >= event_min. A clear reference implementation is sufficient; discuss scaling separately.

import pandas as pd

def attach_prices(decisions, quotes):
    out = pd.merge_asof(
        decisions.sort_values("decision_min"),
        quotes.sort_values("event_min", kind="stable"),
        by="symbol",
        left_on="decision_min", right_on="event_min",
        direction="backward", tolerance=5
    )
    return out.set_index("id").reindex(decisions["id"])

decisions = pd.DataFrame({
    "id": [0, 1, 2, 3, 4, 5],
    "symbol": ["A", "B", "A", "A", "C", "A"],
    "decision_min": [3, 3, 1, 7, 3, 8]
})
quotes = pd.DataFrame({
    "symbol": ["A", "A", "B", "A", "B", "A", "A"],
    "event_min": [0, 1, 1, 2, 2, 2, -1],
    "available_min": [0, 1, 2, 4, 5, 6, 7],
    "price": [100., 101., 200., 102., 202., 103., 99.]
})
out = attach_prices(decisions, quotes)
print([None if pd.isna(v) else float(v) for v in out["price"]])

Actual output from the faulty code

[103.0, 202.0, 101.0, 103.0, None, None]

Explain the result, repair the code, and propose tests that would detect the defect.

Interviewer model answer

The event-time join uses records and revisions that arrived after the decision. Sorting by event time cannot enforce availability. Joining only on availability is also insufficient: the old event arriving at minute 7 must not override event 2. Filter both clocks, then rank by event and revision availability. The fixture's corrections are material: at minute 3, A's price is 101 and B's is 200. This reference is intentionally small-data code.

import pandas as pd

def attach_prices(decisions, quotes):
    prices = []
    for d in decisions.itertuples(index=False):
        eligible = quotes.loc[
            quotes["symbol"].eq(d.symbol)
            & quotes["available_min"].le(d.decision_min)
            & quotes["event_min"].between(
                d.decision_min - 5, d.decision_min
            )
        ]
        if eligible.empty:
            prices.append(float("nan"))
        else:
            latest = eligible.sort_values(
                ["event_min", "available_min"]
            ).iloc[-1]
            prices.append(float(latest["price"]))
    return decisions.assign(price=prices).set_index("id")

decisions = pd.DataFrame({
    "id": [0, 1, 2, 3, 4, 5],
    "symbol": ["A", "B", "A", "A", "C", "A"],
    "decision_min": [3, 3, 1, 7, 3, 8]
})
quotes = pd.DataFrame({
    "symbol": ["A", "A", "B", "A", "B", "A", "A"],
    "event_min": [0, 1, 1, 2, 2, 2, -1],
    "available_min": [0, 1, 2, 4, 5, 6, 7],
    "price": [100., 101., 200., 102., 202., 103., 99.]
})
out = attach_prices(decisions, quotes)
print([None if pd.isna(v) else float(v) for v in out["price"]])

Corrected output

[101.0, 200.0, 101.0, 103.0, None, None]

Tests to expect

Future arrivals cannot change earlier answers; revision before and after release; shuffled quotes invariant; exact boundary ages; late older record; missing symbol; stale quote; empty inputs.

Hint

Which timestamp says when a record describes the world, and which says when it became usable?

Follow-up

How would you implement this for millions of decisions without scanning all quotes for each decision?

Evidence of senior ability

Handles both time axes and revisions, preserves identity and order, and recognises reference-code cost. A possible scale-up is a sweep in availability order, maintaining each symbol's newest eligible event and revision; explain expiry and tie rules. Under available_min >= event_min, the newest event also determines whether any quote passes the age limit.

Model discussion

  • Clarify whether '12 months ahead' means a monthly path for months 1 through 12, a single month-12 value, or a 12-month total. Set the forecast origin explicitly. A sensible exercise convention is a monthly January to December 1817 path from 31 December 1816.
  • Identify the raw and target grains. Use Maker plus Model for handgun keys. Treat missing RS identity as a source issue and do not use forward-fill, row order or a many-to-many join as an undocumented repair.
  • Parse dates explicitly, verify accepted channels and bullet labels, inspect Quantity units and missingness, and check calendar coverage. Keep missing observations distinct from true zero sales.
  • Once the interviewer confirms additive RS rows, aggregate by calendar month and bullet label. Compare row-level and aggregated totals. Keep the original data and the assumptions used.
  • Start with a seasonal-naive monthly baseline: forecast a month using the same month of the previous year. Its value is as a benchmark, not a presumed best model. Do not promise accuracy without evaluation.
  • Use whole future time blocks across all series, with an actual 12-month forecast from each historical origin. An example is training through 1813 to predict 1814, through 1814 to predict 1815, and holding 1816 for final evaluation using data through 1815.
  • Any transformations learned from data, feature selection and parameter tuning must use the training period at each origin. Do not populate later forecast-month lags with realised target values unless the evaluation explicitly represents an updating one-step process.
  • Only use future covariates available at that historical origin. Historical handgun sales and a statement about reliable TF estimates do not establish that future handgun sales are known. Use separate covariate forecasts or scenarios when necessary.
  • Evaluate monthly absolute error by bullet label and aggregate, with an explicit weighting rule if scale varies. Be wary of percentage errors when actuals are zero and of aggregate errors hiding offsetting mistakes. Discuss uncertainty and stockout costs in round two.
  • Return an output with forecast_origin, target_month, horizon, level, bullet or model key, forecast and model_version, plus data-quality findings and assumptions. If intervals are included, evaluate their coverage separately.

import pandas as pd

def monthly_rs(bullets):
    # Contract: the owner has confirmed all RS rows are additive.
    rs = bullets.loc[bullets["Channel"].eq("RS")].copy()

Staged prompts

  • First five minutes: ask for the data contract, including missing ids, invalid quantities and the meaning of a repeated id.
  • Next ten minutes: implement the in-memory reference function and test an exact replay, a conflicting replay and a zero net result.

Model answer

The fixture returns {'X': 0, 'Y': 3}. Count each logical event once, retain zero-valued results, and reject conflicting payloads instead of keeping the first or last silently. The local reference below is O(n) expected time with O(u + s) state for u distinct event ids and s skus.

def net_quantities(events):
    seen = {}
    totals = {}
    for event in events:
        eid = event["event_id"]
        payload = (event["sku"], event["delta"])
        if eid in seen:
            if seen[eid] != payload:
                raise ValueError("Conflicting event payload")
            continue
        seen[eid] = payload
        sku, delta = payload
        totals[sku] = totals.get(sku, 0) + delta
    return totals

Across batches, the processed-event registry must persist. Recording an accepted event and applying its quantity change must happen atomically, for example within one database transaction with a unique event-id constraint. Retrying then becomes idempotent. Define whether corrections are new reversing events or versioned replacements. A fingerprint alone must not silently ignore a changed payload under the same id.

Tests: exact replay within and across batches; conflicting sku or delta; empty input; negative and zero deltas; independent skus; simulated failure and retry. Reject or quarantine invalid records according to a stated policy; do not count them as successful.

Strong evidence and round two extension

Strong candidates distinguish event identity from row equality, keep the implementation simple, and understand why persistent deduplication and total updates must agree. In round two, adapt this to trade corrections, positions and P&L reconciliation after explicitly teaching any required domain conventions.

Model answer

from collections import deque

class RollingMean:
    def __init__(self):
        self.windows = {}
        self.totals = {}

    def update(self, entity, value):
        window = self.windows.setdefault(entity, deque())
        total = self.totals.get(entity, 0)
        if len(window) == 3:
            total -= window.popleft()
        window.append(value)
        total += value
        self.totals[entity] = total
        return total / 3 if len(window) == 3 else None

The reference stores a deque and running total per entity, taking O(1) work per accepted update and O(3s) value storage for s active entities, plus dictionary overhead. On the fourth update for an entity, subtract the outgoing value before adding the new one. State grows with the number of active entities; an eviction policy needs an explicit business contract.

Tests: no output until the third value; correct removal on the fourth; interleaved entities; all zero; negative values; two independent service instances. For long floating-point streams, discuss rounding drift and periodic recalculation or compensated accumulation.

Do not treat duplicate ids or late timestamps as implementation details with an obvious answer. They change the contract. A strong candidate asks about retention, allowed lateness, replay and corrections before selecting a data structure. In round two, extend this to rolling volatility, event time versus clock time and irregular sampling.

def slow_features(rows):
    result = []
    for row in rows:
        history = [
            r["value"] for r in rows
            if r["entity"] == row["entity"]
            and row["minute"] - 3 <= r["minute"] < row["minute"]

Staged prompts

  • Ask for the correct output by hand and the exact interval boundaries.
  • Reveal that the input has two million rows. Ask where the time and memory will go.
  • Ask for a faster outline or implementation, preserving original row order.
  • Introduce missing minutes, then require a comparison against the slow implementation on small random examples.

Model answer

The expected result in original row order is [None, None, None, 15.0, 30.0, None]. The nested scan is O(n squared). Sort by entity and minute, maintain a deque of prior observations and a running sum, remove entries strictly older than minute minus 3, compute the feature, then insert the current observation. The order of those last two steps excludes the current row.

from collections import deque

def fast_features(rows):
    ordered = sorted(
        enumerate(rows),
        key=lambda pair: (pair[1]["entity"], pair[1]["minute"])
    )
    result = [None] * len(rows)
    active_entity = None
    window = deque()
    total = 0
    for original_pos, row in ordered:
        if row["entity"] != active_entity:
            active_entity = row["entity"]
            window.clear()
            total = 0
        cutoff = row["minute"] - 3
        while window and window[0][0] < cutoff:
            _, old = window.popleft()
            total -= old
        if len(window) >= 2:
            result[original_pos] = total / len(window)
        window.append((row["minute"], row["value"]))
        total += row["value"]
    return result

Sorting costs O(n log n); the sweep costs O(n) because each observation enters and leaves the deque once. This in-memory reference also retains the sorted input and output, so total auxiliary memory is O(n), not constant. Its active window size depends on observation density, not simply the number 3.

Compare against the slow reference on small random, shuffled datasets; test the inclusive lower boundary, exclusive upper boundary, single-observation windows and independent entities. Profile representative data and check peak memory. Chunking needs ordered input and window state carried across chunks. A vectorised pandas time-based rolling solution is also acceptable if its closed interval and row alignment are correct.

In round two, discuss how these features enter a forecasting or trading decision, how their information timestamps are established, and how to avoid leakage in evaluation.
