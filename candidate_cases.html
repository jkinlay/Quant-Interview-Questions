Advanced Quant Case Discussions

The interviewer will select one case, introduce further constraints and agree one small component to implement. Define the contract, explain your design, and use a concrete example or failure trace to test it.

Case A Covariance service

A Python service calculates a covariance matrix for 4,000 variables and evaluates q = v.T @ C @ v for user-supplied vectors. Data has missing observations, a changing variable universe and occasional corrections. The process has a 2 GB working-memory budget. A pairwise-deletion implementation returns the following three-variable diagnostic matrix and a negative value of q. Diagnose the numerical and data issues, define a coherent contract, and design an implementation and validation strategy. A short prototype of one component is sufficient.

C = [[1.0, 0.9, 0.9],
     [0.9, 1.0, -0.9],
     [0.9, -0.9, 1.0]]
v = [-1.0, 1.0, 1.0]
reported q = -2.4

Case B Monte Carlo sensitivities

A simulation estimates F(theta) = E[exp(theta*Z)] for standard normal Z, then differentiates it numerically. You are given F(theta) = exp(theta^2/2) and F'(theta) = theta*exp(theta^2/2) as check identities. The estimate becomes unstable as h becomes small. Diagnose whether the implementation is incorrect, statistically inefficient or both. Propose a trustworthy streaming and parallel implementation, its uncertainty estimate and a reproducibility contract. Use theta = 0.2; no finance knowledge is required.

import numpy as np

def sensitivity(theta,h,n,seed):
    rng=np.random.default_rng(seed)
    plus=np.exp((theta+h)*rng.standard_normal(n))
    minus=np.exp((theta-h)*rng.standard_normal(n))
    differences=(plus-minus)/(2*h)
    return differences.mean(),differences.std(ddof=1)/np.sqrt(n)

Case C Event time features

Design a service that emits entity-level features from event-time windows. Records have entity_id, event_id, event_time, available_time, revision and value; a revision can withdraw an event. Deliveries can repeat. Normal arrivals are at most two minutes late, but administrative corrections can refer to any historical date. The process can crash between writing output and checkpointing state. Explain the state model, publication contract, replay behaviour and tests, and implement one agreed component.

Case D Review the forecasting pipeline

Review the supplied bullet-sales forecasting challenge as the prospective owner of its Python pipeline. Establish which requested outputs the source data identifies, define the information available at each forecast origin, and design a reproducible process that supports corrections and historical evaluation. After the first data-contract issues are discussed, the interviewer will supply assumptions so you can proceed to design and one small implementation. Fitting a forecasting model is not required.

bullets_sales.csvDate, Maker, Model, Bullets, Channel, Quantity
handgun_sales.csvDate, Maker, Model, Quantity

TF denotes sales together with firearms and RS denotes replacement sales. The original requested output is a 12-month replacement-sales forecast by bullet type and aggregated by handgun maker and model.
